# SRUM migration reference

`SRUDB.dat` is the existing repository fixture, SHA-256
`fb3b913c8a94fae7d73f6d5641af9dd1a0040133744e07927082214a436d5c00`.
It contains 2,355 provider records; timeline mode emits 2,361 entries.
This is older data and does not establish recent Windows 11 compatibility.

`rust-baseline.json` was captured before the Python migration using a release
wheel built from dfir-ogre-common commit
`21ff914100f7d2ee0ea9207587ea3cb1de2d9358`, with the Windows plugin's SRUM XML
from commit `802f9b2ae5073f833ab9d591885ac7f96c29fa99`.
The reference covers all 14 configured providers, JSONL, CSV and normalized JSONL,
with timeline and empty-field output independently enabled and disabled.
Normalized JSONL additionally verifies the typed-value-derived record IDs and
metadata IDs. The baseline is generated by the original Rust parser, not the
new implementation, and must not be regenerated with the Python parser.

Every file's digest includes every complete record and retains duplicates.
JSON object keys and output records are sorted for comparison because the Rust
runtime's timeline entries can appear in different orders between processes.
CSV digests retain the header order and all cell values. No timestamps, IDs,
metadata fields or other values are removed from the comparison.
See `tests.srum_reference.output_digest` for the precise digest algorithm.

To reproduce the capture, first install a common wheel built from the source
commit above, then run from the Windows plugin repository:

```python
import json
from pathlib import Path
from tempfile import TemporaryDirectory
from dfir_ogre_common import parse_srum
from tests.srum_reference import output_cases, run_reference

with TemporaryDirectory() as folder:
    cases = {
        name: run_reference(parse_srum, Path(folder, name), options)
        for name, options in output_cases()
    }
    print(json.dumps(cases, indent=2))
```

The port intentionally preserves the original parser's ID-blob decoding and
FILETIME subsecond scaling. Correcting those independently would change existing
results and normalized IDs. OLE timestamps retain nanosecond precision internally
through the common runtime's timestamp parser rather than Python `datetime`.

Run the migration checks with:

```sh
.venv/bin/python -m unittest tests.test_srum tests.test_esedb -v
```
